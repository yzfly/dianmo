# 点墨 Dianmo · 设计

> 指尖一点，落字成墨。让 Surface 等 Windows 触屏设备上的中文输入，像手机输入法一样顺手。

需求来源见 `TODO.md`。本文是实现的依据；改设计先改这里。

## 1. 问题

Surface 拆掉键盘后只剩触屏，而 Windows 的输入体验是为实体键盘设计的：

- 系统触摸键盘又宽又大，两只手要大范围移动；没有九宫格；第三方输入法的候选框是给鼠标用的小浮窗，手指很难点中。
- 豆包、微信等成熟产品的语音输入，要靠长按右 Alt、Ctrl+Win 这类**实体键**触发，纯触屏用不了。
- 没有现成的开源方案；安卓输入法也不能在 Windows 上跑（WSA 已停止支持）。

手机屏幕更小，输入却更好用，靠的是：候选词就在键盘上、按键有反馈、手势多、九宫格和双拼、一键语音、键盘弹出时页面自动让位。点墨要把这些搬到 Windows 上。

## 2. 体验设计（对标手机输入法）

**形态**
- 默认**停靠在屏幕底部、全屏宽**，横屏时高度约占屏幕的 38%（可调）。之后会加悬浮和左右分体（拇指模式）两种形态。
- **不遮挡**：键盘注册为 AppBar，占用屏幕底部的工作区，最大化的窗口会自动缩上去，就像手机把页面顶上去。
- **不抢焦点**：点键盘不会让目标应用失去焦点和光标。

**候选条**（键盘最上面一行）
- 左边是预编辑区，显示正在输入的拼音（如 `ni hao`），右边是横向滑动的候选词，最右边是展开箭头，点开是全屏候选网格。
- 没在输入时，候选条换成工具栏：语音、布局切换、符号、剪贴板（以后加）、收起键盘。

**布局**
| 布局 | 说明 |
|---|---|
| 26 键全拼 | 默认 |
| 26 键双拼 | 小鹤（默认）/ 自然码 / 微软 / 搜狗，设置里选；键面小字标注所选方案的韵母。微软、搜狗的 ing 在「；」键上：宽屏布局本来就有这个键（加 ing 小字），手机布局在 a–l 行末尾多一个「；」键；组字时这个键交给引擎，没在组字时是标点 |
| 九宫格拼音 | 左侧一列显示可能的拼音（选了就锁定音节）和常用标点 |
| 英文 26 键 | Shift 单击是下一个字母大写，双击锁定大写 |
| 数字九宫格 / 符号面板 | 中文模式下默认全角标点（「中文时用全角标点」关掉后，中文布局的标点键换成半角；符号面板的中文页不变） |

**手势与反馈**
- 按下时弹出放大的气泡；长按或上滑一个键，输入它右上角标的数字或符号（q→1 …）。
- 按键音（v0.2.0，默认关）：按下（不是松开）就响，字符键和功能键（空格、删除、回车、Shift…）两种声音；音量小/中/大、音色清脆/柔和。实现见 §3「按键音」。
- 删除键：长按连续删除，向左滑清空正在输入的拼音。
- 空格键：左右滑动移动光标；输入时按空格上屏第一个候选。「空格上屏首选」关掉时（v0.2.0），输入中按空格 = 先原样上屏打出的字母（同回车），再输入一个空格——用于中英混打（例如打 `iphone` 后直接空格继续），比「空格什么也不做」或「只插空格留着拼音」更符合手机输入法里关掉这个选项的人的预期。
- 回车：输入中按回车，原样上屏拼音或字母；没在输入时就是普通回车。
- 输入中点标点，先上屏第一个候选，再输入这个标点。

**Surface 宽屏布局（TODO #19，2026-10-06；已实现，实现细节以本节为准）**

Surface 横屏是 1440×960 DIP（13 英寸，1 DIP≈0.19mm）。手机布局拉到全宽后，每个键 140 多 DIP 宽，比实体键还宽，宽度全浪费在把键拉宽上。键盘宽度 ≥ 1100 DIP 时用宽屏布局，参照 iPad Pro 12.9 的大屏键盘，把空间用来放更多的键；窄屏和竖屏（Surface 竖屏 960 宽）仍用手机布局。
- **高度**：宽屏五行，标准高度 1440 宽时约 353 DIP（屏高的 37%），候选条约 58 DIP，键高约 57 DIP。高度档位只缩放键行，键高不低于 52 DIP（最矮档也是）。
- **26 键（全拼 / 小鹤 / 英文）改五行**，键宽单位 = 字母区宽 / 14.5（开着编辑区时约 86 DIP，关掉约 99 DIP）：
  - 第一行：`Esc`、常驻数字行 `1–0`、`- =`、⌫。数字直接点就上屏，不用长按，也不用进 123 面板。
  - 第二行：`Tab`（长按 = Esc）、`q–p`、中文 `【】、`（英文 `[]\`）。
  - 第三行：`大写`（大写锁定）、`a–l`、中文 `；“`（英文 `;'`）、⏎。
  - 第四行：⇧、`z–m`、中文 `，。？`（英文 `,./`）、⇧。中文输入中左边的 ⇧ 换成「分词」（同手机）。
  - 底行：`Ctrl`、`Win`、`Alt`、`Fn`、符号、空格、中/英、`← ↑↓ →`（↑↓ 上下两个半高键）、收起。
  - 符号键像实体键盘一样带上档：点 ⇧ 后数字行变成 `！@#¥%……&*（）`（英文 `!@#$%^&*()`），`-` → `——`，`，` → `《` 等；上档字符也可以长按或上滑输入。
  - 字母键角标从数字改成符号（q 行 `～ · —— + = _ 「」『』`，a、z 行同手机）；小鹤双拼的韵母小字保留。
  - 全角/半角标点随中英文模式；中文模式下再看「中文时用全角标点」设置。
  - 123 面板仍保留：符号面板底行有「123」页签；数字输入框获得焦点时自动打开。
- **数字面板（123）**：数字区限宽（键宽单位不超过 100 DIP）、居中，`1 2 3` 在上（同手机），右侧 ⌫ `.` ⏎；左边 3×3 运算符 `+ - * / % = ( ) :`、返回、`,`；右边 `Tab @ #`、`¥/$ & _`、`行首 ↑ 行尾`、`← ↓ →`。方向键、行首行尾按下就发、按住连发。
- **九宫格**：九宫格保持拇指布局的大小（不拉伸）；右边依次放 ⌫/重输/⏎ 一列、2×4 的常用标点（中文 `，。？！、：；……`）、一个数字小键盘（`1–9`，`0` 和 `.`），数字直接点上屏。
- **候选条**：
  - 宽屏候选字号 24 DIP（手机约 19），首选是强调色加粗，底下有一块浅色圆角底，更醒目；拼音在左上角 15.5 DIP。设置「候选字号」小/标准/大/特大 = ×0.85/1/1.15/1.3（注释字号变化减半），候选栏高度不变（特大在宽屏是 31 DIP 字放在 36 DIP 的行里）。
  - 宽屏一行能放下更多候选（1440 宽约 18 个）。
  - 候选带注释时（如简拼的全拼）在候选右边用小字显示。**待办**：rime_ice 的 corrector.lua 会清掉拼音注释，要在 dianmo-rime 里给简拼候选补全拼注释（另开任务）。
  - 展开的候选网格格子更大（宽 ≈ 2 倍键高，高 = 键高），右侧一列：收起、上页/下页、⌫、重输、⏎；翻页按整行滚动，翻到底部附近时加载更多。
- **快捷键 / 编辑工具栏**：
  - 不在输入时，候选条是工具栏：左边是编辑工具（撤销、重做、选择、全选、剪切、复制、粘贴，窄屏和九宫格再加 ← →，长按到行首、行尾），右边是语音、布局、电脑键（窄屏和九宫格）、剪贴板、表情、收起。宽屏 26 键开着编辑区时，编辑工具已经在编辑区里，工具栏只留右边那几个。
  - 窗口太窄放不下时，先去掉 ← →，再从右往左去掉编辑工具。
- 实现：`dianmo_core::Action::Key(KeyChord)`，`TextSink::send_chord` 用一次 `SendInput` 发出；controller 先上屏正在组字的内容，再发组合键（同方向键）。

**电脑按键（TODO #22，2026-10-06；已实现）**：Surface 本质是 Windows 电脑，很多操作离不开 Ctrl、Shift、Alt、Win、Esc、Fn、F1–F12、方向键。触屏上要都能按出来，但默认界面仍像手机一样简洁。
- **宽屏 26 键的完整排布**见上一节。
- **修饰键（Shift / Ctrl / Alt / Win / Fn）用触屏的三种按法**：
  - 点一下是单次：亮起，只作用于下一个键，用完自动松开。
  - 双击（350ms 内）是锁定：一直有效，再点一下松开。适合 Ctrl 加多次方向键。锁定的 Ctrl / Alt / Win 是真的按住（见下面「锁定 = 真按住」）。
  - 按住时用另一只手指点其他键，是真正的组合键（多点触控，和实体键盘一样）；按住期间用过的修饰键松手后不会再亮起。
  - 可以叠加，例如 Ctrl+Shift+T。
  - **Win**：单独点一下 = 按一次 Win（开始菜单）；长按 Win 才是亮起（单次），亮起时再长按是锁定。已经有别的修饰键亮着时，点 Win 是加入组合：截图 Win+Shift+S 的按法是「⇧、Win、S」，或者按住 Win 点 ⇧ 再点 S。
- **有 Ctrl / Alt / Win 时，键盘进入快捷键状态**：
  - 字母、数字、标点键发虚拟键码，不经过输入法（Ctrl+C 不会变成拼音）。全角标点键按它所在的物理键发（`，` = `,` 键）。空格、⏎、⌫、Tab、方向键也会带上修饰键（Win+空格、Ctrl+⏎、Ctrl+⌫ 等）。
  - 只有 Shift 时：字母大写、符号键换上档；方向键、Tab、⏎ 带 Shift 发（Shift+方向键选中文字、Shift+Tab、Shift+⏎ 换行）。
  - 常用组合在键面上用强调色小字提示：Ctrl 时 A 全选、C 复制、V 粘贴、X 剪切、Z 撤销、Y 重做、S 保存、F 查找、H 替换、W 关闭、T 新标签、N 新建、O 打开、P 打印、R 刷新；Win 时 D 桌面、E 文件、V 剪贴板、R 运行、I 设置、L 锁屏、S 搜索（加 Shift 是截图）、A 通知、X 菜单。
- **Fn 层**（单次或锁定，规则同上）：数字行变成 F1–F12（`-` `=` 是 F11、F12），方向键变成 Home、End、PgUp、PgDn，⌫ 变成 Del，Esc 键变成 `` ` ``。F 键可以和 Ctrl/Alt/Shift 叠加（Alt+F4：点 Alt、Fn、F4）。
- **常驻编辑区**（TODO #26，宽屏 26 键；#32 重排）：键盘最右边常驻两列：撤销 重做 / 选择 全选 / 复制 粘贴 / 剪切 删词 / 清空 剪贴板。「清空」= Ctrl+A 再 Del，「删词」= Ctrl+⌫。方向键在底行，不重复放。行首、行尾给「选择」「剪贴板」让了位置，改在 Fn+← →（Home / End）和选择栏里。粘贴键下面用小字预览剪贴板里的文字。
  - 开着编辑区时字母键宽约 86 DIP（不小于 80）。
  - 「设置 › 键盘 › 横屏显示编辑区」可以关掉（`settings.ini` 的 `edit_area=false`），关掉后宽度还给字母区，工具栏换回编辑工具。
- **窄屏和九宫格**：不常驻这些键。空闲工具栏里有「电脑键」按钮，点开紧凑面板（12 列 × 4 行）：F1–F12；Esc Tab Home End PgUp PgDn Del ⌫；⇧ Ctrl Alt Win PrtSc 空格 ↑ ⏎；返回 `` ` - = [ ] \ ' `` ← ↓ →。（这里 F 键已经直接显示，所以没有 Fn，换成了截图键 PrtSc。）
- **底层**：`dianmo_core::KeyChord { ctrl, shift, alt, win, key: Option<KeyCode> }`，`KeyCode` 是 ASCII 字母/数字/空格/美式键盘标点、`EditKey`（含 PageUp/PageDown）、F1–F24、Insert、PrintScreen；`key: None` 是单独按修饰键（单按 Win）。常用的有常量 `KeyChord::COPY / PASTE / UNDO …`。另有 `Action::KeyDown(KeyCode)` / `Action::KeyUp(KeyCode)` 和 `TextSink::key_event(key, down)`：单独按下、抬起一个键（虚拟键 + `MapVirtualKeyW` 扫描码，扩展键带 `KEYEVENTF_EXTENDEDKEY`；`KeyCode` 也包含 Ctrl/Shift/Alt/Win/CapsLock/Menu 这些键本身），给直通的「电脑键盘」布局（TODO #31）用；按下前同样先上屏组字。`SendInputSink` 一次 `SendInput` 发出：修饰键（左 Ctrl、左 Shift、左 Alt、左 Win）依次按下 → 键按下抬起 → 修饰键倒序抬起。
- **锁定 = 真按住**（2026-10-06）：单次和手指按住的修饰键仍是一次性的组合键（上面那样一个 `SendInput` 发完）。锁定的 **Ctrl / Alt / Win** 则真的按着：
  - 锁定后第一个键之前发 `KeyDown`，之后一直按着，其它键只发它们自己（组合键里去掉已经按着的修饰键，否则 `SendInputSink` 发完会把它抬起）；再点一下解锁时发 `KeyUp`。所以锁定 Alt 连点 Tab 能停在任务切换界面里往后翻，解锁就切过去；锁定 Ctrl 连点 Z 只按一次 Ctrl。
  - 只锁定、没有按别的键就解锁，什么也不发（不会单按 Win 弹开始菜单、单按 Alt 激活菜单栏、单按 Ctrl 切输入法）。
  - 锁定期间要上屏文字（候选、符号、长按 / 上滑的副字符、剪贴板粘贴）、移动光标（空格拖动、触控板）、开语音、设置、收起时，先把按着的修饰键抬起，锁定仍亮着，下一个键之前再按下。换面板、换布局 / 中英、进出电脑键盘、键盘收起、在应用里点了别处（焦点因触摸变化）、托盘 / 设置换输入模式时也抬起。
  - **Shift 锁定不变**：它是打字的大写锁定（字母上屏大写、符号换上档），字和符号不是按键发的；真按住 Shift 会让上屏的文字、在应用里的点按（Shift+点击扩选）都带上 Shift，单独按放 Shift 还会切换目标应用输入法的中英。只有组合键里需要时才带 Shift。
  - 微信输入法的「按住说话」热键是按住左 Ctrl + 左 Win：同时锁定 Ctrl 和 Win 再按键，两个一起按着，可能弹出它的语音浮窗。
- **管理员窗口**（TODO #23）：普通权限的进程既收不到管理员窗口的焦点事件，也没法往里打字（UIPI 限制）。所以点墨通过一个「使用最高权限运行」的计划任务启动，不弹 UAC。桌面图标和开机自启都走这个任务；直接双击 exe 时，如果发现自己不是管理员权限，就转去启动这个任务。

**选择、复制与剪贴板（TODO #32，2026-10-06；已实现，以本节为准）**：Windows 触屏上的长按选择、复制和粘贴很难用（选区把手小、菜单难点）。点墨在键盘上把这一套做好，让用户不用在应用里长按。
- **触控板**：
  - 长按空格（450ms）进入触控板模式：键面隐去，整块键区变成触控板，显示提示和手指位置。手指拖动时，光标在应用里上下左右移动（发方向键）：慢拖约 14 DIP 走一个字、26 DIP 走一行；拖得快步长成倍放大（最多 5 倍）。每次以横向或纵向为主，另一个方向的零头逐渐清掉，横拖不会串行。
  - 触控板模式下，另一根手指点一下就开始选择（之后的移动都带 Shift），再拖动就扩大选区；选择中再点一下，按词扩选一次（Ctrl+Shift+→）。
  - 松手退出触控板模式；如果选过东西，就自动打开「选择栏」。
  - 拖动空格（不长按）仍是左右移动光标。原来的「长按空格 = 语音」已去掉，语音用麦克风键和语音球。
- **选择模式**（编辑区 / 工具栏的「选择」键；或者点「复制」后 350ms 内剪贴板没变，说明没有选中任何东西，就自动进入）：
  - 候选条换成选择栏：`‹字 ›字`（Shift+←/→）、`‹词 ›词`（Ctrl+Shift+←/→）、`︿行 ﹀行`（Shift+↑/↓）、行首、行尾（Shift+Home/End）、全选。移动类按钮按下即发、按住连发。这时键盘上的方向键、Home/End、PgUp/PgDn 也自动带 Shift。
  - 选择栏右侧：复制、剪切、粘贴、删除、完成；点了就退出选择模式。打字（字母、标点、空格、回车、退格）也会退出。
- **复制以后**（剪贴板里来了新文字，键盘正显示着）：
  - 键区中间弹出约 1 秒的「已复制」（单次计时器，不轮询），新内容排到剪贴板栏第一个。
  - 空闲时的候选条变成剪贴板栏：横排卡片（最近的在前，第一张描边），可左右滑动，点一张就粘贴它；右边是「全部」（打开剪贴板面板）、✕（关掉，回到工具栏）、收起。用户开始打字、关掉或收起键盘后回到工具栏。
  - 粘贴键（编辑区）上用小字预览当前剪贴板里的文字；剪贴板变成图片、文件或私密内容时预览消失。
  - 电脑键盘布局下只记录历史，不弹提示、不换栏。
- **剪贴板历史**（`crates/dianmo/src/clipboard.rs`）：
  - 后台线程建一个 message-only 窗口，用 `AddClipboardFormatListener` 监听，`WM_CLIPBOARDUPDATE` 时读 `CF_UNICODETEXT`，经 `HostProxy::post` 交给界面线程；有事件才处理，空闲 CPU 仍为 0。
  - 内存里最多 30 条未固定的文本（同样的文字只留一条，挪到最前；超过 10 万字的不记）。固定的条目（最多 50 条）存到数据目录的 `clips.txt`（`%APPDATA%\Dianmo\clips.txt`，`--instance` 时在 `Dianmo-<名字>` 下），一行一条，`\` 和换行转义；以后可以选择加密。
  - 不记录：带 `ExcludeClipboardContentFromMonitorProcessing` 的内容，`CanIncludeInClipboardHistory` 或 `CanUploadToCloudClipboard` 为 0 的内容（密码管理器）；密码框获得焦点期间的复制（靠焦点监听，所以要开着「点输入框时自动弹出」）；点墨自己写剪贴板引起的变化（按剪贴板序号区间跳过）。
  - 剪贴板面板（工具栏 / 编辑区 / 剪贴板栏的「剪贴板」）全屏显示卡片网格（固定的在前，带图钉），每张最多两行；点一下粘贴并回到键盘，长按出现「固定 / 取消固定」「删除」两个按钮，顶部有「返回」和「清空」（清掉未固定的）。
  - 点卡片粘贴时，默认用 Unicode `SendInput` 直接打出这段文字，不动系统剪贴板。超过 2000 字、或者**含换行**（打字会按回车，聊天软件里会直接发出去）时，走剪贴板：在监听线程里保存剪贴板现有的全部内存块格式 → 写入文字 → 发 Ctrl+V → 等 600ms 让应用读走 → 恢复原内容；剪贴板打不开时退回打字。

**电脑键盘布局（TODO #31，2026-10-06；已实现，以本节为准）**：在全拼、小鹤、九宫格、英文之外，再加一个「电脑键盘」布局。它就是一块触屏版的物理键盘，键位和笔记本键盘一致。
- **键位**（六行，15 个键宽；功能键行 3/4 高）：
  - `Esc F1–F12 PrtSc Del`
  - `` ` 1–0 - = ``、Backspace
  - `Tab q–p [ ] \`
  - `Caps a–l ; '`、Enter
  - `Shift z–m , . /`、Shift
  - `Ctrl Win Alt`、空格、`Alt Fn Ctrl`、方向键（倒 T 形，↑↓ 各半高）
  - Fn 层：← → ↑ ↓ 变成 Home、End、PgUp、PgDn，Del 变成 Insert（PrtSc 常驻在功能键行）。媒体键、菜单键没有做。
  - 键盘总高度和其他布局一样（不用重新停靠），顶部细栏 28–38 DIP，Surface 横屏键高约 51 DIP。竖屏（960 宽）也能用，键比较矮。
- **直通**：这个布局下点墨不组字，候选条隐藏。每个键按下时发 `KeyDown`、松手发 `KeyUp`（虚拟键码加扫描码），和插了一块物理键盘一样。所以目标应用当前的输入法（微信、豆包、搜狗、微软拼音）照常组字（Surface 实测：记事本里是微信输入法，点 `n i h a o` 出现微信输入法的候选窗），快捷键、终端也都能用。
- **自动重复**：按住任何键，400ms 后每 40ms 重发一次 `KeyDown`（中间不发 `KeyUp`），和物理键盘的连发一样；松手才发 `KeyUp`。
- **修饰键**：沿用「电脑按键」一节的按法（点一下单次、双击锁定、按住组合；Win 单点 = 开始菜单，长按亮起），但这里是真的按下：
  - 修饰键在它作用的第一个键按下之前才发 `KeyDown`：单次的（和锁定的 Shift）在那个键松手后抬起；锁定的 Ctrl / Alt / Win 之后一直按着，解锁才抬起（同「锁定 = 真按住」）；手指按住的一直按着，松手才抬起。所以按住或锁定 Alt 连点 Tab 都能停在任务切换界面，按住 Ctrl 点 C 再点 V 只按一次 Ctrl。
  - 只点一下修饰键（没有配别的键）什么也不发。长按 Shift / Ctrl / Alt（350ms）就真的按下，直到松手：长按 Shift 再松开 = 单独按一次 Shift（多数中文输入法用它切中英）；按住 Ctrl 时另一只手在应用里滚动 = 缩放。
  - **注意**：微信输入法的「按住说话」热键是按住左 Ctrl + 左 Win。电脑键盘里同时按住 Ctrl 和 Win（或锁定后再按住另一个）会被微信输入法当成按住说话；Ctrl+Win+←/→ 切换虚拟桌面时可能弹出它的语音浮窗。
- **键面**：上档字符用小字标在左上角；Shift 生效时整块键盘换成上档字符、字母大写；Caps 键右上角有指示灯（点墨自己记的状态：点 Caps 就切换，物理键盘改了 Caps 时可能不同步），Caps 开着时字母显示大写。
- **切换**：布局菜单的「PC 电脑键盘」、托盘「输入模式 ▸ 电脑键盘」、设置「常规 › 输入模式」进入；顶部细栏：「← 返回」（回到之前的布局）、语音、收起。离开时把还按着的键和修饰键全部抬起。设置 `input_mode=pc` 记住（`input_mode=keyboard|voice|pc` 取代旧的 `pc_keyboard` / `voice_mode`，旧键仍能读）。
- **底层**：`Action::KeyDown/KeyUp(KeyCode)` → `TextSink::key_event`（dianmo-win `send_key_event`）。

**悬浮球（TODO #30，2026-10-06；已实现，以本节为准）**：键盘收起后，不再显示左边缘的长条把手，改成一个悬浮球。语音模式下的语音球也是这个球。
- **外观**：
  - 直径 48 DIP，和新图标同一套视觉：蓝→紫→品红的渐变圆，中间一个白色书法点，带柔和投影。
  - 逐像素透明的窗口（`UpdateLayeredWindow`），圆边抗锯齿，透明的角不接收点击。
  - 球的外沿离工作区边缘始终留 10 DIP（避开 Windows 的边缘手势区）。闲置 3 秒后缩成 32 DIP 的半透明小球（仍离边缘 10 DIP，不再半隐到屏幕外：露出的半个球从 0 像素开始，一拖就是系统的边缘手势）；按下或拖动时恢复 48 DIP。语音模式下例外：每次进入语音模式（以及语音模式下本次运行第一次出现球）时，球完全露出 10 秒，旁边弹一个小气泡「点一下说话，长按展开键盘」（点气泡或 10 秒后消失）。
- **交互**：
  - 拖动：松手后贴到最近的左边缘或右边缘，位置存进 `settings.ini`（`ball_edge=left|right`、`ball_y=<0–1，球心在工作区高度中的位置>`），下次启动恢复。
  - 键盘模式：点一下或长按，弹出键盘。
  - 语音模式：点一下开始或结束语音，长按（0.55 秒）展开键盘。
  - 录音中（引擎正在启动或收音）：球上有呼吸光圈，并从边缘出来；光圈动画只在这时播放。
  - 不抢焦点，和键盘窗口一样。
- **接口**（dianmo-win → App）：`App::on_ball(BallEvent::{Tap, LongPress, Moved(BallPos)})`；`HostControl::set_ball_state(BallState::{Idle, Listening})`；位置用 `HostOptions::ball_pos` 传回。

**语音模式 / 语音球（TODO #29，2026-10-06；已实现，以本节为准）**

以语音为主要输入方式时，键盘可以缩成悬浮的语音球，是点墨最小的形态。语音球就是上一节的悬浮球（48 DIP，不另做一个 56 DIP 的球）。
- **进入 / 退出**：键盘布局菜单里的「语音球」磁贴（开启语音模式并收起键盘）；托盘「输入模式 ▸ 语音球」；设置「常规 › 输入模式」。设置 `input_mode=voice`，下次启动保持。语音模式下悬浮球总是显示（不受「显示悬浮球」开关影响）。
  - **随时能退出（2026-10-06 热修）**：语音模式下，任何「显式显示」请求（长按球、托盘单击 / 菜单、再次双击桌面图标）都会显示键盘；键盘显示时，候选条工具栏最前面是醒目的强调色按钮「退出语音模式」（电脑键盘布局的细栏中间也有），布局菜单里的磁贴变成选中状态的「退出语音球」。点它们关闭语音模式，键盘留在屏幕上。
- **用法**：
  - 点球开始语音，球显示录音光圈；再点一下结束。
  - 长按球展开完整键盘（托盘也可以呼出）。键盘收起后回到语音球。
  - **语音模式下点输入框不自动弹出键盘**，只有球；离开输入框时，已经展开的键盘照常收起。
- **语音引擎**（托盘「语音引擎 ▸ 微信输入法 / 豆包输入法 / 豆包语音（第三方） / 系统语音（Win+H）」或「设置 › 语音」，设置 `voice_engine=wetype|doubao_ime|doubao|system`，默认微信输入法；不可用的引擎在菜单里标「未安装」或「未就绪」，设置页里显示原因）：
  - 点墨模拟所选引擎的语音热键，并看麦克风占用判断是否真的开始收音，做法以 `docs/research/voice.md` 和 `crates/dianmo/src/voice.rs` 为准。热键：微信输入法 `LCtrl+LWin+LShift`（Shift 夹在中间，免得弹开始菜单），豆包输入法「免按模式」`右 Alt+空格`（读 `%APPDATA%\DoubaoIme\conf\config.json` 的 `voice.voiceShortcutMode`；要求打开它的「全局语音快捷键」，否则目标窗口的输入法不是它时 `Alt+空格` 会打开窗口的系统菜单），豆包语音（第三方小工具）读它的 `HotKey`（F6）。
  - **不再自动回退到系统语音（2026-10-06 用户要求）**：所选引擎不可用，或热键发出 1.5 秒内没开始收音，只提示原因（键盘显示着就在键区中间提示，最长 4 秒；语音球形态下在球旁边弹气泡 5 秒），不打开 Win+H，也不会每点一次就开 / 关一次系统语音面板。系统语音只在用户在托盘里手动选它时使用（每点一次 = Win+H 一次）。
  - **管理员窗口**：引擎（普通权限运行）看不到发往管理员窗口的热键，不管热键是谁发的（Surface 实测：提权的点墨和普通权限进程发的热键，在普通记事本前台时微信输入法都在约 0.3 秒内开始收音，在管理员记事本前台时都没反应）。所以点墨发热键前先看前台窗口的完整性级别，比引擎进程高就直接提示「微信输入法收不到管理员窗口里的语音快捷键（Windows 权限隔离），请在普通窗口里使用」，不等 1.5 秒；普通权限的辅助进程帮不上忙，没有做。
- **麦克风键**（工具栏、电脑键盘顶部细栏）用同一个引擎，点一下开始、再点一下结束；录音中（启动或收音）麦克风键是红色圆底白色话筒。点之前先松开锁定的修饰键（电脑键盘里按着的键和修饰键也会抬起），清掉未上屏的组字，免得热键变成别的组合键、或被输入法吃掉。
- **收起与取消**：键盘模式下收起键盘、以及换引擎时，取消正在进行的语音（不出结果）；语音模式下收起键盘不影响球上的语音。退出点墨时如果还在收音，也会取消。
- **剪贴板**：微信输入法（目标输入法不是它时）和豆包语音会借剪贴板交付结果，点墨在会话开始时保存剪贴板、结束后放回。语音进行中、以及结束后 3 秒内的剪贴板变化都不进点墨的剪贴板历史，也不弹「已复制」（这期间用户自己复制的内容同样不记录）。
- **轮询**：只在会话进行中（含结束后等结果的约 2.5 秒）用键盘窗口上的单次计时器每 300ms 查一次状态；空闲时没有计时器，CPU 为 0。

**语音**
- 麦克风键和语音球用所选的语音引擎（见上一节），默认微信输入法；所选引擎不可用时只提示原因，不再回退到系统语音（#37）。点墨自己不带识别模型，也不额外占性能。
- 离线语音（如 sherpa-onnx + SenseVoice）放到以后，作为可选项。

**自动弹出 / 收起**
- 输入框一获得焦点，键盘自动出现，离开输入框就收起（用 UI Automation 监听焦点）。
- 键盘收起后有悬浮球，托盘也有图标，可以手动呼出（语音模式下点输入框不弹出，见「语音模式」）。
- 关掉 Windows 系统触摸键盘的自动弹出，避免两个键盘同时出来。

## 3. 技术选型（2026-10-06 调研后定稿）

调研了两个方向（界面框架、输入架构），结论和理由如下；冒烟测试已在 Surface 上通过。

**语言：Rust**。没有运行时，内存小，启动快，符合「Surface 性能有限」（TODO #10、#14）。

**界面：原生 Win32 + Direct2D / DirectWrite（`windows` crate 0.62.2），动画以后用 DirectComposition**
- 窗口过程完全自己写，不抢焦点的做法可控：`WS_EX_NOACTIVATE|WS_EX_TOPMOST|WS_EX_TOOLWINDOW`，`WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`，`WM_POINTERACTIVATE` 返回 `PA_NOACTIVATE`，显示时用 `SW_SHOWNOACTIVATE`。
- `WM_POINTER` 原生多点触控，两只拇指同时按也不会丢键。
- DirectWrite 渲染中文清晰；`GetMessage` 阻塞，空闲时 CPU 为 0。
- 冒烟测试结果：exe 264KB，私有内存约 45MB，空闲 CPU 0，前台窗口不变。
- 不选的方案和原因：
  - Slint、egui：底层 winit 不处理 `WM_MOUSEACTIVATE`，而且把第一根手指当鼠标，第二根手指按下时会让第一根「抬起」，双拇指打字会出错。
  - Tauri / WebView2：一点就抢焦点，还要额外 100–200MB 内存。
  - Freya、GPUI：需要 MSVC 或 Skia。

**输入架构：近期用「键盘进程 + `SendInput` 上屏」，长期加一个轻量的 TSF 客户端**
- **M1–M3**：组字只在点墨的候选条里进行，上屏用 `SendInput(KEYEVENTF_UNICODE)`；退格、回车、方向键发真实的虚拟键（方向键要加 `KEYEVENTF_EXTENDEDKEY`）。Win32、UWP、Chromium、Electron、Office、终端都能用。
  - 限制：管理员权限的窗口收不到（UIPI 限制）；只读扫描码的程序（游戏、远程桌面）不行；没有内嵌在应用里的预编辑。
- **长期**：写一个很薄的 Rust TSF 输入法 DLL（参考 windows-chewing-tsf），只当客户端，librime 仍然跑在点墨进程里。好处：
  - 应用里能显示内嵌预编辑；
  - 能拿到可靠的「输入框获得焦点」信号，以及输入框类型（数字、密码、网址）；
  - 管理员窗口也能用。

  所以现在的代码要按「点墨进程是服务端」来写。
- 不选「复用小狼毫 Weasel」：它的候选词拿不到点墨的键盘上，除非 fork 它的 C++ 代码。

**引擎：librime 1.17.0 官方 MSVC x64 版（`rime-33e7814-Windows-msvc-x64.7z` 里的 `rime.dll`）**
- 这个 `rime.dll` 已经静态链接了 lua、octagram、predict 插件，只依赖系统 DLL。
- 运行时用 `LoadLibrary` 加载，再调 `rime_get_api()` 拿函数指针表；绑定代码自己写，不用现成的 crate（都不活跃）。注意设置 `data_size`，返回的对象只能用 librime 自己的 `free_*` 释放。
- 方案来自雾凇拼音 rime-ice：`rime_ice`（全拼）、`double_pinyin_flypy`（小鹤）、`t9`（九宫格）。
  - rime-ice 的 t9 方案从 PR #1451 起依赖 iOS 专有的 `t9_processor`，要用之前的版本（2025-01-14），或者去掉这个处理器。
  - 九宫格的键盘显示要用候选注释里的拼音，不显示数字。
- 词库在打包时预编译，首次启动不用等；OpenCC 数据一起发。
- **个人设置（模糊音）**（v0.2.0）：在用户目录写 `<schema>.custom.yaml`，由子进程 `dianmo.exe --deploy-user` 只重编改动的方案到用户目录的 build（约 1 秒，词典仍用安装包里预编译的），完成后运行中的引擎 `reload()`（约 0.1 秒）。部署期间照常能打字。数据包换版本后，旧的用户 build 自动作废并重新部署。
- 双拼方案：小鹤、自然码、微软、搜狗（rime-ice 自带，共用词典）。设置改方案时 `RimeEngine::set_shuangpin`，键面提示表在 dianmo-ui `layout.rs`（`shuangpin_table`，数据来自各方案 yaml 的拼写运算）。
- 主程序里的接线（`app/rime_ui.rs`）：模糊音在引擎启动前先写 custom.yaml；需要部署时起子进程，设置页显示「正在应用模糊音…」，完成后 reload。reload 和用户词库的导入 / 导出 / 清空 / 计数都把 `RimeEngine` 暂时移到后台线程做（期间键盘用内置引擎顶着，不在组字时才移走），做完放回，UI 线程不卡；一次一件，其余排队。导入导出用系统的打开 / 保存对话框，属于设置窗口。

**语音：Windows 自带的语音输入**（2026-10-06 起是回退方案：默认用微信输入法的语音，见 §2「语音模式 / 语音球」和 `docs/research/voice.md`）
- 一次 `SendInput` 发出 Win↓ H↓ H↑ Win↑。点墨不抢焦点，所以文字会进入目标输入框。
- 依赖：要联网，要打开「在线语音识别」，当前输入语言要是中文。这台 Surface（Win10 LTSC）已装中文语音组件 `Language.Speech~~~zh-CN`，在线语音识别也已开启（2026-10-06 确认）。

**按键音（v0.2.0，`crates/dianmo/src/sound.rs`）**
- 四个几 KB 的 WAV（48 kHz 单声道 16 位，清脆 / 柔和 × 字符键 / 功能键，`res/sounds/gen.py` 合成）编进 exe。
- 打开按键音时才起一个音频线程：WASAPI 共享模式、事件驱动，启动时就打开默认输出设备（初始化好但不 Start），首个按键不用等设备。关掉按键音线程退出、释放设备，不占内存和 CPU。
- 键盘在**按下**时发 `UiAction::KeyClick`（排在本次按键的输入动作之前），主程序只做 `SetEvent`；音频线程醒来把声音混进缓冲区（最多 4 个声音叠加，快打不截断）、Start；播完缓冲区排空就 Stop，回到无限等待（空闲 CPU 0）。预排的音频控制在两个设备周期内，连按时新声音的延迟也小。目标：按下到出声 < 30 ms（WASAPI 周期 10 ms + 设备延迟）。
- 停顿 3 秒后的下一次按键先确认默认设备没变（插拔耳机）；WASAPI 出错就丢掉流、下次重开；WASAPI 完全不能用时退回 winmm 的 `PlaySound(SND_MEMORY|SND_ASYNC)`（只在需要时动态加载，延迟大、会互相打断）。不用 XAudio2：它的引擎线程常驻，还要多加载一个 DLL。

**自动弹出（M2）**
- 用 UI Automation 的焦点变化事件（放在 MTA 线程上，用 CacheRequest 一次取齐控件类型、只读、密码等属性），并且只在约 500ms 内刚有过触摸时才弹出，和系统键盘的规则一致。
- 关掉系统触摸键盘的自动弹出：Win10 设 `HKCU\Software\Microsoft\TabletTip\1.7\EnableDesktopModeAutoInvoke=0`，Win11 设 `TouchKeyboardTapInvoke=0`。不要停用 TabletInputService，Win+H 依赖它。
- AppBar 只在键盘显示时注册，退出时一定要发 `ABM_REMOVE`；Explorer 重启（`TaskbarCreated` 消息）和屏幕旋转后要重新注册。

**输入法冲突**：目标应用里如果开着微软拼音、搜狗，`SendInput` 发 Unicode 字符不会触发它们组字，基本不受影响。以后可以在中文语言下加一个美式键盘布局，键盘显示时切过去作兜底，这个待验证。

## 4. 代码结构

```
crates/
  dianmo-core/   纯逻辑   Engine / TextSink 接口、InputController（手机输入规则，唯一实现处）
  dianmo-ui/     纯逻辑   键盘界面：布局、候选条、手势、气泡；通过 Canvas 画，通过 View 被驱动
  dianmo-rime/   Windows  librime 动态加载 + Engine 实现；方案和词库的准备、预编译
  dianmo-win/    Windows  窗口宿主（不抢焦点、WM_POINTER、DPI）、Canvas 的 D2D 实现、SendInput、Win+H、AppBar、系统键盘设置
  dianmo/        Windows  主程序：把上面几块组装起来，托盘；安装登记 / 卸载 / 检查更新 / 诊断（install.rs、update.rs、diag.rs）
  dianmo-setup/  Windows  安装包 DianmoSetup-<版本>.exe：小 stub + 追加在尾部的压缩负载（dist 目录），以及打包工具 dianmo-pack
data/rime/       方案、词库（脚本拉取，不进 git）
```

**模块之间的接口**（以代码为准）
- `dianmo_core::Engine` / `TextSink` / `InputController` / `Action`。
- `dianmo_ui::Canvas`：圆角矩形、文字、裁剪；坐标都是 DIP。`dianmo_ui::View`：resize / paint / pointer / timer / set_input_state …，返回 `Response { repaint, actions, timer_ms }`。

**宿主的事件循环**：触摸事件 → `View::pointer` → `UiAction::Input(a)` → `InputController::handle(a)` → `View::set_input_state(...)` → 需要时重绘。

依赖方向：`dianmo` → 其余四个；`dianmo-win`、`dianmo-rime`、`dianmo-ui` → `dianmo-core`；`dianmo-win` → `dianmo-ui`（只用 Canvas / View 接口）。

## 5. 性能（硬约束）

- 空闲时 CPU≈0：没有轮询，没有常驻动画，焦点监听用事件。
- 内存：私有内存目标 < 80MB（含 librime 和词库）。2026-10-06 实测（Surface，2880×1920）：键盘显示时约 32–36MB（用过电脑键盘、剪贴板面板等之后 43MB 左右），其中 WARP 软件渲染的整宽表面约 16–19MB、librime 约 10MB、焦点监听 / 剪贴板监听 / 悬浮球各 1–2MB。键盘收起 5 秒后释放渲染设备和表面，降到约 15MB；再显示时重建（约 50ms CPU）。
- 按键到界面更新 < 16ms。
- 构建在 Surface 上进行：低优先级、`-j 2`，打包后清理 `target`。

## 6. 构建与开发流程

- **工具链**：
  - Surface：Rust stable `x86_64-pc-windows-gnullvm` + llvm-mingw（`C:\dev\tools\llvm-mingw`，提供 clang、lld、dlltool），不装 Visual Studio。`.cargo/config.toml` 开启 `+crt-static`，exe 只依赖系统 DLL。
  - 服务器：只做快速检查。纯逻辑 crate 用 `cargo test`；Windows crate 用 `cargo check --target x86_64-pc-windows-gnullvm`，不链接。
- 代码在服务器 `~/yzfly/dianmo`（唯一真源），Surface 只作构建和测试机，工作目录是 `C:\dev\dianmo-<名字>`。
- `scripts/surface/`：
  - `ps.sh`：在 Surface 上执行 PowerShell。
  - `sync.sh <名字>`：同步代码。
  - `build.sh <名字> [cargo 参数]`：同步后低优先级构建，排队执行。
  - `gui.sh [超时]`：在用户的桌面会话里执行，排队执行。
  - `shot.sh <out.png>`：截屏。
  - `clean.sh <名字> [--target]`：清理工作目录或 target。
- 用户正在用这台 Surface：GUI 测试要短，测完关掉自己开的窗口，不能留下错误弹窗。

### 6.1 发布：安装包、卸载、更新（2026-10-06）

- **安装包** `DianmoSetup-<版本>.exe` = `dianmo-setup.exe`（stub，约 200KB）+ 负载 + 32 字节尾部索引。负载是 dist 目录逐个文件的 zlib 流（`miniz_oxide`，纯 Rust；解压时校验 Adler-32），由 `dianmo-pack` 在打包时追加（`package.sh <名字> --setup`）。stub 是通用的，不用 `include_bytes!` 把 20MB 编进去。
- **权限**：安装包以当前用户运行（manifest `asInvoker`）。所有东西都是每用户的（`%LOCALAPPDATA%\Dianmo`、HKCU、快捷方式），只有注册「最高权限」计划任务需要管理员，单独用 UAC 提权执行 `dianmo.exe --register-task`。好处：拒绝 UAC 时照样装好（只是不能给管理员窗口打字）；从运行中的（已提权的）点墨发起的升级继承权限，不弹 UAC；任务已存在且指向同一 exe 时（重装）完全不弹；装完以普通用户身份启动点墨，不需要「降权启动」的技巧。
- **流程**：解压到 `<安装目录>.new` → 用新的 `dianmo.exe --quit` 优雅关闭正在运行的点墨（绝不强杀：会留下 AppBar 占位和改过的系统键盘设置；旧版本不认识退出消息时改发 `WM_CLOSE` 给键盘窗口；对方提权而我们没有、消息被 UIPI 挡住时，提权再执行一次）→ 目录改名替换（失败回滚；目录被占用时改为覆盖复制）→ `dianmo.exe --install`（快捷方式、「应用和功能」登记、计划任务、启动）。登记逻辑和卸载（`--uninstall`）放在 `dianmo.exe` 里，名字、注册表项、`--instance` 后缀只有一处定义。
- **更新**：WinHTTP 读 GitHub Releases `latest`（JSON 用内置的小解析器，不引 serde_json），下载 `DianmoSetup-*.exe` 到 `%TEMP%`（校验大小和 GitHub 给的 SHA-256），以 `/S` 运行。自动检查：启动 1 分钟后一次，之后每天最多一次；检查线程按小时醒来看墙钟时间，没有 UI 线程定时器。
